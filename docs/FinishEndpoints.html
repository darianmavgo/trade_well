New this pass: stage_orders. stage_orders.RunJob takes the latest scan's NEW rows in scan_market_buy_signal, sizes them against each account's live cash and equity, writes stage_order rows, and marks each signal STAGED or DISMISSED so a rerun never stages it twice. It is called by orchestrator stage_orders [--dry-run|--live] and by GET /cron/stage_orders[?dry_run=1]. cron.yaml now runs it at 18:15 ET Sun to Thu, after the 18:00 scan and before the 09:28 submit. Signals whose next session has passed are dismissed as expired. Four new tests cover staging once, dry run, expiry and no accounts. Builds and all tests pass. Not deployed.

Cross-cutting gaps to finish

  1. Two scan_market implementations (above). This is the largest break of the "one package, three contexts" rule left. run-all-jobs also runs the old CLI path and never calls stage_orders.
  2. Unauthenticated /runtime and /dbsync on the public URL.
  3. Dry run only exists on /cron/stage_orders. Add ?dry_run=1 to submit_orders and manage_exits too, so every job can be previewed from GAE.
  4. Only account_state retries and emails on failure. The other cron handlers email a report on success, but a crash before that point is only logged.
  5. Names. Packages are plural (stage_orders, submit_orders, manage_exits, job_runs) but their tables are singular (stage_order, submit_order, manage_exit, job_run). CLI display commands health-checks, active-trades, staged-orders, run-all-jobs are hyphenated, unlike every job name. Renaming tables needs a migration on the deployed, replicated DB, so pick one convention first.
  6. No endpoints for the display commands. active-trades, staged-orders and health-checks exist only in the CLI; the dashboard's /api/tables shows part of the same data.
  7. Untested: auth and job_runs have no tests, and cmd/orchestrator has none.

Suggested order

  1. Deploy stage_orders and the cron fixes, then call /cron/stage_orders?dry_run=1 against the real account and read the output before the first scheduled run.
  2. Collapse the two scan_market paths.
  3. Put /runtime and /dbsync behind auth.
  4. Add ?dry_run=1 and job-run records to the other jobs.
  5. Decide the table naming convention, then migrate.
Table lists come from each package's CREATE TABLE statements; routes from appserve, dashboard and schwaber's oauthhttp. Not run against the live service. Which routes are protected by Basic Auth was read from code, not tested.
