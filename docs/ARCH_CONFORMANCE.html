What passes

  • Dependency direction. Only hits for trade_orchestrator inside SW/BT are comments and the /tmp/trade_orchestrator default folder string.
  • Core job names match end to end (CLI case, pkg/ dir, /cron/<job>, cron.yaml, withDBSync): account_state, scan_market, stage_orders, submit_orders, manage_exits, check_health. appserve/cron.go keeps one cronJobs list shared by the CLI and HTTP.
  • submit_orders is one implementation across contexts. pkg/submit_orders.RunJob is called by both /cron/submit_orders and the CLI (RunCommand, which run_all_jobs also uses). It takes a context.Context and a *log.Logger, accounts run independently, every live run writes a job_run row, and the report email and log line are identical from either entry point. Covered by pkg/submit_orders/job_test.go; no test sends real email.
  • BT strategy SQL is split into numbered stage files (01_schema, 02_calc_*_slice, 03_calc_signals). Nesting is shallow: deepest is 3 paren levels in gld_decline/04_annual_cagr_audit.sql.
  • BT cmd/ binaries are ~5-line wrappers.
  • Allowed shell-outs only in TO: dbsync runs Litestream (permitted). cronclient calls gcloud (no Go equivalent used, but not on the rule's allowed list).

Violations

Rule 2: one implementation, thin cmd/

  • trade_orchestrator/pkg/appserve/cron.go: the handlers for scan_market, manage_exits and check_health still loop over accounts, build report rows and send the email inline instead of calling one pkg/<job> entry point, and stage_orders builds its own email in the handler. submit_orders was fixed this way (RunJob); the same treatment is open for the others. Biggest remaining Rule 2 gap in TO.
  • trade_orchestrator/cmd/orchestrator/main.go is much thinner than reported on 2026-09-23 (476 lines). runSubmitOrders, runCheckHealth and others delegate to pkg/<job>.RunCommand. runScanMarket (42 lines) still has some setup logic of its own.
  • schwaber/cmd/schwaber/main.go is 290 lines and killswitch.go no longer exists. Not re-audited for logic.
  • os.Exit/os.Args in backtestgosqlite/pkg/dataflare/main.go and pkg/cliutils.
  • exec.Command in BT pkg/: pkg/ui/main.go:290 runs a hardcoded absolute path (/Users/darianhickman/Documents/wc_2022/backtest_all.sh); pkg/dataflare shells out to open.
  • Direct stdout writes instead of io.Writer in BT pkg/: gridsearch (59), backtest (31), runner (25), audit_shared (24), scoreboard (20), strateval (19), ticker_scan (15). SW and TO are nearly clean (SW oauthcli, trader/logging.go; TO dbsync, dashboard).

Rule 3: consistent names

  • Outliers still live as primary CLI commands: health-checks, run-all-jobs, active-trades, staged-orders. run-all-jobs is also passed to withDBSync under the hyphenated name. No documented deprecated aliases.
  • Only submit_orders has a [<job>] log prefix so far ([submit_orders]). Other prefixes in pkg/ are [appserve] (29 uses), [dbsync], [dashboard]. submit_orders is also the only job that records a job_run row from its own package besides scan_market and stage_orders; manage_exits, account_state and check_health do not.
  • The submit_orders email subject is now submit_orders -- <outcome> rather than the bare job name, an intentional exception documented in the TO README. The other jobs are unchanged.
  • Env vars APP_FOLDER, SCHWAB_DB_PATH, MARKET_DB, GCS_BUCKET, STRATEGY_ALLOWLIST appear in READMEs. My check for other undocumented env vars returned nothing, but I did not confirm the check itself ran correctly.
