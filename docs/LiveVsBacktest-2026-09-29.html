5. Dollar P&L from the executions

Run this against the restored database. It walks each filled order, including sells nested under a bracket, and sums trade-transaction net amounts. The strategy total in the table above is this output, restricted to MARA, PDD, TECL, and TSLL.

python3 - <<'PY'
import json, sqlite3
db = sqlite3.connect("/tmp/reconcile-20260929/orchestrator.db")

def legs(order):
    out = []
    for leg in order.get("orderLegCollection") or []:
        inst = (leg.get("instrument") or {}).get("symbol")
        out.append((leg.get("instruction"), inst))
    return out

def execution(order):
    notional = qty = 0.0
    for act in order.get("orderActivityCollection") or []:
        if act.get("activityType") not in (None, "", "EXECUTION"):
            continue
        for leg in act.get("executionLegs") or []:
            px, q = leg.get("price") or 0, leg.get("quantity") or 0
            if px > 0 and q > 0:
                notional += px * q
                qty += q
    return (notional / qty, qty) if qty else (None, 0)

def walk(order, acct, depth=0):
    side = sym = ""
    found = legs(order)
    if found:
        side, sym = found[0]
    px, qty = execution(order)
    if sym in ("TSLL", "MARA", "PDD", "TECL", "VOO"):
        print(f"{'  '*depth}{acct} {(order.get('closeTime') or '')[:19]} "
              f"{order.get('status')} {side or '':4} {sym:6} exec={px} qty={qty} "
              f"oid={order.get('orderId')}")
    for child in order.get("childOrderStrategies") or []:
        walk(child, acct, depth + 1)

print("== fills ==")
for acct, raw in db.execute("SELECT account_number, raw_json FROM account_state_order"):
    walk(json.loads(raw), acct)

print("\n== trades ==")
for acct, td, net, raw in db.execute(
        "SELECT account_number, trade_date, net_amount, raw_json "
        "FROM account_state_transaction WHERE transaction_type='TRADE' ORDER BY trade_date"):
    j = json.loads(raw)
    sym = ""
    fees = 0.0
    for item in j.get("transferItems") or []:
        if item.get("feeType"):
            fees += abs(item.get("amount") or 0)
        inst = item.get("instrument") or {}
        if inst.get("symbol"):
            sym = inst["symbol"]
    if sym in ("TSLL", "MARA", "PDD", "TECL", "VOO"):
        print(f"{td[:19]} {acct} {sym:6} net={net} fees={fees:.2f} oid={j.get('orderId')}")

How a row was read

  • Returns from the commands are fractions. 0.05 is five percent. The percentages in this write-up are already multiplied by 100.
  • signal_match / outcome_match in the command output is whether GenerateSignals fired that symbol on that date, then whether the live outcome and exit reason agree with the replay. MARA and PDD are 0/0. The filled TSLL rows are 1/0 because the tracker status is still OPEN while the replay is CLOSED on a profit target.
  • mara_tree, pdd_tree, and sig-voo-buy-tecl enter on the next session's limit in the simulator. tsll-daily-one-share is replayed on the signal bar, at the close plus 0.20% slippage. With no stored signal date, MARA and PDD were replayed as if the fill day were the signal day, which shifts a next-day strategy by one session.
  • walk_forward and check_overfit compare in-sample and out-of-sample backtests. They do not read live fills, so they were not run for this report.
